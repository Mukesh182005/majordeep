1Executive summary

DeepSentinel AI is a web platform that takes an uploaded image, audio file or video, runs it through a detection pipeline for that media type, and returns a probability that the media is manipulated or AI-generated, a three-way verdict (AUTHENTIC, MANIPULATED, INCONCLUSIVE), visual evidence (heatmaps, spectrograms, timelines), and a downloadable PDF report with a SHA-256 hash.

Image

Two public scene-level AI-image detectors fused in log-odds space (0.75 / 0.25) make the decision. A face-crop EfficientNet-B4 is shown but kept out of the verdict. A forensic suite (ELA, CFA, metadata, C2PA) adds context.

Audio

A Light CNN (LCNN) over LFCC features, trained in this repo on ASVspoof 2019 LA, is the only input to the audio verdict. It scores each 4-second window to build the timeline.

Video

Samples 1 frame/s (max 32), crops the largest face with MTCNN, scores frames, runs the scene ensemble on the worst frame, then 11 stages with hand-set fusion. A trained face-swap model is in progress.

What this evaluation does and does not cover The audio model is the only detector here with a held-out evaluation file from a public benchmark. That benchmark is studio-quality English read speech. The model has not been evaluated on phone calls, real-world recordings or other languages (LCNN_SCOPE_NOTE, audio_pipeline.py). The image ensemble was chosen on a 560-image measurement that is recorded only in a source-code comment. The video verdict uses hand-set fusion weights.

Design principles that run through the codebase

  • Measured, not assumed. Detectors are kept, reweighted or dropped based on measurements. Example: umm-maybe/AI-image-detector scored AUC 0.469 and was removed.
  • Refuse rather than guess. An uncertainty band around the threshold returns INCONCLUSIVE. An unflagged screenshot is INCONCLUSIVE, never AUTHENTIC.
  • Weights must match their calibration. The audio checkpoint is loaded only if its SHA-256 matches the calibration file. A missing image checkpoint is flagged untrained-backbone everywhere.
  • Heuristics carry zero weight until proven. Audio heuristics get weight only if their bootstrap 95% AUC lower bound on dev is above 0.6. None passed.

4End-to-end request lifecycle

This is what happens between a user dropping a file on the Upload page and downloading the PDF.

  1. Limits check. The SPA calls GET /api/upload/limits for allowed extensions, the size limit (MAX_UPLOAD_MB, default 100), duration limits (audio 600 s, video 300 s), enabled media types and guest retention hours.
  2. Upload. POST /api/upload (multipart). Middleware rejects an over-size Content-Length with 413 before reading the body. The router checks the media type is enabled (else 403), checks duration (else 400), applies per-user/IP rate limits (upload_events), stores the file, computes SHA-256, and creates a jobs row with status queued.
  3. 202 Accepted. The response contains id, case_reference, sha256, file_size_bytes, uploaded_at.
  4. Enqueue. enqueue_analysis(job_id) sends jobs.analyze to Redis. In eager mode it runs in-process.
  5. Live progress. The SPA calls POST /api/jobs/{id}/links for signed ws_url / report_url (5-minute TTL), then opens /api/jobs/{id}/ws. It falls back to polling GET /api/jobs/{id}/status.
  6. Inference. The worker sets processing and calls analyze(media_type, path, EVIDENCE_DIR, job_id). The pipeline returns an AnalysisResult: probability, verdict (or a verdict override for audio), confidence, model name/version, weights_status and an evidence dictionary. Evidence images are written as EVIDENCE_DIR/<job_id>_*.png.
  7. Persist. The verdict, probability, model info, JSON-safe evidence and processing_ms are written to the job. Status becomes done, or failed with a user-facing message (corrupt media, missing detector, missing file).
  8. Result. GET /api/jobs/{id}/result returns JobResultOut, including experimental, experimental_reason and the fixed disclaimer. Evidence images come from GET /api/jobs/{id}/evidence/{kind}.
  9. Report. POST /api/jobs/{id}/report builds the PDF, stores its SHA-256 in reports, and returns report_reference and download_url. GET /api/jobs/{id}/report streams it with an X-Report-SHA256 header. GET /api/reports/{ref}/verify checks a report reference.
  10. Deletion / retention. DELETE /api/history/{id} removes the upload, every evidence file, the report PDFs and the database rows. Guest jobs are purged automatically after RETENTION_HOURS (72).

6.1 Scene-detector ensemble Third-party pretrained

For each detector, P(AI) = 1 − P(real class), where the real class is found in that model's own label map ("real", "human", "hum", "authentic"). This stops a model with unusual label names from being silently mis-scored. The fused score is sigmoid(Σ wᵢ·logit(pᵢ) / Σ wᵢ).

Why these two models and this fusion? They were chosen by measurement, not by model card. A comment in image_pipeline.py records a test on 560 held-out images: 200 real COCO/Flickr photos and 360 from SD 2.1, SDXL, SD3, DALL-E 3, Midjourney v6, Flux.1-dev, and Gemini "Nano Banana" / Nano Banana Pro. Each was scored as the original file, as a normalised JPEG and as a simulated screenshot. Log-odds averaging was chosen over max-of-experts so that one over-eager model can't flag a real photo on its own.

6.2 EfficientNet-B4 face model Informational

A torchvision EfficientNet-B4 (ImageNet init) with its classifier swapped for a single logit, trained at 224 px. It runs in float32, because float16 autocast overflowed to NaN on some inputs. Its per-face score and Grad-CAM heatmap are shown, but face_model_in_verdict=False keeps it out of the verdict.

Why is it excluded from the verdict? The comment in config.py says it was trained on StyleGAN faces only. On real vs modern-AI photos with faces it flagged 21% of real faces and only 15% of AI faces, so it can't tell them apart on current generators. It stays out until a retrained model is validated.

6.3 Screenshots and forensic suite Unvalidated

  • Recapture handling: uniform viewer bars are cropped before any pixel analysis. A screenshot that the detectors don't flag is reported INCONCLUSIVE, because recapture destroys the evidence an AUTHENTIC verdict needs.
  • Camera-trace absence (no CFA trace) only corroborates a detector that has already fired. It was missing in all 196 real web JPEGs measured (source comment), so on its own it means nothing.
  • Declared provenance (C2PA trainedAlgorithmicMedia, generator parameters in metadata) raises the floor. The floor values are hand-set.

7.1 Front end: LFCC Trained & evaluated

Each window: 20 ms Hamming (320 samples) zero-padded to a 512-point FFT, 10 ms hop, centred frames, 20 linear triangular filters from 0 to 8 kHz, natural log with a 1e-10 floor, orthonormal DCT-II keeping c0–c19, plus deltas and double deltas over 3 frames. That gives a 60 × 401 matrix. Features are rounded through float16 exactly as during training.

Why LFCC? The front end was chosen on the dev set by ml/evaluation/select_asvspoof_frontend.py; a log-Mel checkpoint also exists for comparison. Linear filters keep high-frequency resolution where vocoder artefacts tend to sit. Serving imports the training feature code, so the deployed model sees exactly the features it was evaluated on. That's why the waveform is deliberately not peak-normalised: normalising shifts c0.

7.2 Network: Light CNN (LCNN)

Nine convolution blocks with Max-Feature-Map activations (split channels in half, take the element-wise max), BatchNorm and four 2×2 max-pools. Then global average pooling and a head of Dropout 0.3 → Linear 32→64 → BN → ReLU → Linear 64→1. The checkpoint is about 600 KB.

Why LCNN? It's the architecture used by the ASVspoof anti-spoofing baselines, so results can be compared with published systems. It's small enough to run on CPU. Max-Feature-Map acts as a learned feature selector, which suits narrow spectral artefacts.

7.3 Serving safeguards

  • The checkpoint named in paper/config/audio_calibration.json is loaded only if its SHA-256 matches (7ca31fd0…). Any other weights make the detector unavailable, rather than producing probabilities nobody measured.
  • The verdict thresholds are frozen on dev in frozen_audio_config.json: decision threshold 0.497 from dev, band ±0.08. That gives AUTHENTIC < 0.417, MANIPULATED ≥ 0.577, INCONCLUSIVE in between.
  • AUDIO_MODEL_SOURCE=legacy switches back to hand-set rules and marks every result experimental: true.

8.1 Face-swap model In progress

A trained face-swap detector is being built to replace the hand-set face signal:

  • Data: face crops from FaceForensics++ (c23) and Celeb-DF v2, 32 frames per video, the same MTCNN setup and margin as backend/app/ml/faces.py, official splits by video, and an audit that fails if any video or identity appears in two splits.
  • Scoring contract the UI already supports (VideoForensicsView.jsx): face_tracks[], one entry per tracked face, scored as the mean of the top 25% of its frame scores. The video score is the highest track score. A calibrated segment_timeline is built from the same scores. With no face track, the UI says "No face found: face-swap check not applicable."
  • Status: the backend wiring lives on ml/faceswap-wire, which is not merged into this branch and has no checkpoint or results file here. No accuracy figure is claimed for it.

9Decision logic and verdicts

Image and video (platform default)

FAKE_THRESHOLD = 0.50, UNCERTAIN_BAND = 0.08

  • p < 0.42 → AUTHENTIC
  • 0.42 ≤ p < 0.58 → INCONCLUSIVE
  • p ≥ 0.58 → MANIPULATED

app/config.py and app/ml/base.py classify(). Pipeline-specific overrides apply, e.g. an unflagged screenshot → INCONCLUSIVE, no scene detector loaded → AUTHENTIC impossible.

Audio (frozen on ASVspoof dev)

Threshold 0.497 (from dev), band ±0.08

  • p < 0.417 → AUTHENTIC
  • 0.417 ≤ p < 0.577 → INCONCLUSIVE
  • p ≥ 0.577 → MANIPULATED

paper/config/frozen_audio_config.json, set via verdict_override in audio_pipeline.py.

Why a three-way verdict?

Refusing is a feature. Scores near the threshold are where detectors make most of their mistakes. Returning INCONCLUSIVE there, and for inputs whose evidence was destroyed (screenshots, missing detectors), is more honest than forcing a binary answer. "No manipulation detected" never means "proven authentic".

13Security, privacy and deployment

Authentication & links

  • JWT in an httpOnly cookie: SameSite=Lax, Path=/api, Secure in production.
  • No ?token= query parameters. Reports and the WebSocket use HMAC-signed URLs with exp and sig, scoped to one job, 5-minute TTL.
  • Production boot fails with the placeholder or a short JWT secret (minimum 32 characters).

Abuse controls

  • Upload rate limits per user and per IP (Compose defaults: 20/h users, 3/h guests).
  • X-Forwarded-For is never trusted. X-Real-IP is trusted only from TRUSTED_PROXIES.
  • Early 413 on Content-Length. Duration and media-type limits.
  • Security headers middleware. HSTS in production.

Privacy & retention

  • Stored: the upload, its SHA-256, evidence images, the result and reports.
  • Guest jobs are deleted with all files after 72 h by the hourly beat purge.
  • Registered users' jobs are kept until deleted. Deletion removes every derived file.

Error hygiene & observability

  • Unhandled errors return an opaque message plus a request_id. The full traceback goes to server logs only.
  • Validation errors never echo the raw body back.
  • JSON logs in production, with a request-ID header on every response.

14Limitations and open items

Model-level

  • Audio is evaluated only on ASVspoof 2019 LA (studio English read speech). It is weak on attack A17 (26.90% EER). Untested on phone, real-world or non-English audio.
  • Image ensemble selection numbers live in a code comment, not a results file. The served ensemble is third-party; new generators may evade it.
  • Image face model is excluded from verdicts (21% / 15% flag rates on real / AI faces). Its 99.98% validation accuracy is in-distribution only.
  • Video verdict uses hand-set fusion weights with no labelled-video evaluation. Stages 1, 4–9 and 11 are unvalidated heuristics. Sampling at 1 fps (max 32 frames) can miss manipulated segments.
  • Face-swap model is not on this branch. No metric is claimed.

Input-level (from docs/LIMITATIONS.md)

  • Heavy JPEG compression, social-media re-encoding and screenshots destroy forensic signals.
  • Low-bitrate (< 64 kbps), very short (< 2 s) or noisy audio reduces reliability. ENF needs audible mains hum.
  • Metadata can be stripped or forged and is treated only as supporting evidence.
  • SHA-256 proves a file hasn't changed since hashing. It does not prove the content is genuine.
